# CLAUDE.md

Guidance for Claude Code when working in this repository.

## What this is

* The original DOS **Philips FM900 Field Personality Programmer**.
* A Linux re-implementation of its EPROM image builder.
* A browser version of that builder (`web/`), in the style of a web CPS, named **Web FPP (FM900 CPS)**.

## Layout

The original DOS files are reference material. **Never modify them.**

| `firmware/FM92R.ram.txt` | **Generated** RAM/I-O cross-reference (`python3 firmware/tools/ramxref.py FM92R > firmware/FM92R.ram.txt`): for each `$00`–`$FF` address, the routines that read/write/RMW it and the bits they test/set. Regenerate after renaming routines in `FM92R.ann`. The meanings are hand-written in FIRMWARE.md §16. |
| `firmware/fork/` | **FM92R firmware fork**: editable source for new functionality (README there). `FM92R.asm` is generated once by `mkasm.py` (from the master + `FM92R.ann`) and hand-edited from then on. Never re-generate over it. New code goes in `fork.asm` (free area `$15AF–$1B3F`). `asm6805.py` is a stdlib 6805 assembler. `python3 build.py` assembles `-D FORK=0`, which must equal `FM92R.BIN`, then `FORK=1` → `build/FM92R-fork.BIN` (checksums fixed), used with `fm900gen.py --master-file`. Rules: every original label is pinned with `.at` (never move or resize original code, because of immediate-built pointers, `jmp $0188,x` and jump tables). Hook in by overwriting with JSR/JMP + NOPs inside `.if FORK … .else <original> .endif`. Don't edit `$0000–$00FF` or `$1B40+`. Two variants from one source, by feature flags (`build.py` VARIANTS): `FM92R-intro.BIN` (INTRO+NOHOOK) and `FM92R-fork.BIN` (INTRO+FREQ+NOHOOK, "enhanced"). Stock check = FORK=0 FREQ=0 INTRO=0 NOHOOK=0. NOHOOK = the three `brset 4,$11` (off-hook) tests in `scan_task` ($0EC0/$0EF1/$0FC7) become NOPs: no off-hook scan stop and no continuous off-hook tone (FIRMWARE.md §7.3); test `NoHookScan`. INTRO = at start-up, "00" on the head plus a Morse callsign on the beep tone (`$29.7`; uart_bit toggles `$29.4` ≈600 Hz), blocking, from `MO_TABLE` (`$197C`, marker `MOR1` at `$1978`), filled by `mkradio.py --callsign` / Web FPP. FREQ: Rx frequency on the head, cycling in 2-character windows after the channel number. Radio images must be built with `mkradio.py` (fm900gen inputs + fills the per-channel frequency table at `$19B0`, marker `FQT1` at `$19AC`, decoded from each slot's Rx divider), because plain fm900gen/Web FPP leave it empty. Fork RAM: `$B6`–`$BD` (external RAM gap), soft timer `$57` (FREQ); INTRO's Morse (18 wpm, 1 unit = 66.5 ms) is timed by counting flips of bit 5 of the ISR tick counter `$28` (every 13.3 ms; the 27 ms soft timers can't give 15–20 wpm), so `$58` is spare. Never send to the head while `$1C.5` (keep-alive reply due) or `$1A.1` (FIFO busy). Head display: `$82` = left char, `$80` = right. `sim6805.py` runs routines in tests; `stackdepth.py` (run by build.py) fails the build if the fork is deeper than the factory master (the static bound is pessimistic: stock = 27). Test: `cd firmware/fork && python3 -m unittest test_fork`. |

| `firmware/FM92RS.ann` | **Generated** by `python3 firmware/tools/portann.py FM92R FM92RS` (ports FM92R names/comments by normalised-instruction alignment, keeps one only if the first 3 instructions match, prints a mapped/dropped/new-code report). ## Rules when changing fm900gen.py

* **Faithful port.** Each method is a faithful port of an FM900.EXE routine, and the comments give the routine's linear address in the unpacked image (e.g. `FUNC 0x5A5D`). Preserve the original quirks: operation order, OR/AND on top of master contents, x87 80-bit comparisons done with `Fraction`, and FM92-VHF storing L power as 2.
* **Regression test.** These must stay byte-identical when built with `fromjob` and the date stamped in each reference `.BIN`:
  * `fm900/JOBS/2MHAM`
  * `fm900/JOBS/SH`
  * `fm900/JOBS/SHC`
  * `fm900/JOBS/80CHCB`
  * `fm900/JOBS/477`, first 20 channels, with channel 11's `F_SCAN1` flag cleared (that `.CHL` was edited after its `.BIN` was made)
* **Unsupported paths.** FM93, FM97WP/waterproof and the selcall tone editor are not implemented. The relevant routines are listed in FM900_FORMAT.md §5.

## Facts confirmed from both sides

* `.CHL` flag word: 0x10 = VOTE, 0x20 = ECON, 0x40 = SELCALL, 0x4000 = C/R. The FM900.EXE entry-screen order is CTCSS, C/R, VOTE, ECON, SELCALL. The firmware agrees: VOTE drives the linked-slot voting ring, and slot byte6 bit7 (SELCALL) gates the selcall code.
* Power: "off" = CPU in `STOP` with RAM kept. Only RESET (on/off key or the FM92R head cable's on/off wire, via IC407 + PA5) switches it on, and each press toggles. The FM92R also needs the head to answer each `$E4` poll with `$49`, or it powers down after about 3 s (FIRMWARE.md §6.1, §6.3). `$49` is **not** a power-off command.
* FM92L and FM92R differ only in the operator interface. L = local front-panel keys, display and LEDs. R = 1200 baud single-wire serial link to a remote control head. The data layout is identical.

## Firmware facts (from the disassembly only)

* Head commands (FM92R): `$44` = PTT **press**, `$45` = release; `$46` = hook/monitor press, `$47` = release. `$44`/`$46` auto-release after 1.5 s unless repeated (FIRMWARE.md §6.2).
* CTCSS: software digit s8 = 1–7 (0x1F34 bit0) is needed for any tone; decode also needs h5 = 2/5/8 (0x1F34 bit2). fm900gen does not cross-check h5 against s8. On FM92R the tone is only sent while `$11.4` = PA7 high AND head `$46` held (FIRMWARE.md §7.2; FM92L uses PA7 alone, so `$46` is the head's hook report; PA7 = hook switch, inferred).
* Every FM92R routine is named in `FM92R.ann` (no `sub_` labels left). Keep it that way: name new finds there, mark guesses "(inferred)" in the comment, then regenerate `FM92R.lst`, `FM92RS.ann`/`.lst` (portann) and `FM92R.ram.txt`.

## Re-doing the FM900.EXE disassembly

1. Unpack EXEPACK. The stub is at CS = 0x29B1; the real entry is 1963:0014 and DGROUP is 0x230F.
2. Convert the MS C floating-point emulator calls back to x87 opcodes:
   * `CD 34..3B` → `9B D8..DF`
   * `CD 3D` → `90 9B`
3. Disassemble with Capstone in 16-bit mode.
